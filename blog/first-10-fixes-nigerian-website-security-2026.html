The first 10 fixes for Nigerian website security

April 2026 | 8 min read

We scanned 1,180 Nigerian websites this year. Banks. Fintech. Government. Healthcare. Universities. SME stores. Across all of them, the same 10 problems kept showing up.

The good news: most take under 15 minutes to fix. The annoying part: they keep showing up because nobody has a list. So here is the list.

Ranked by impact-per-minute. Number 1 is the highest leverage. Number 10 is the polish step. If you do all 10, your site will be in the top 5% of Nigerian websites for security posture.

Across the 1,180 sites we scanned: 64% are missing HSTS, 71% are missing Content-Security-Policy, and 58% have no cookie consent banner. The bar is genuinely low. Clearing it puts you ahead.

The 10 fixes (in priority order)

FIX 01
Add HSTS to your main domain
Time: 2 minutes | Impact: very high
HSTS (Strict-Transport-Security) tells browsers to ALWAYS use HTTPS for your domain. Without it, users on public WiFi can be silently downgraded to HTTP and their session cookies stolen. This is the single most important header for a Nigerian website where customers use cybercafe / hotel / event WiFi.
What to add: Strict-Transport-Security: max-age=31536000; includeSubDomains

Where: nginx → server block → add_header. Apache → .htaccess → Header always set. Cloudflare → SSL/TLS → Edge Certificates → enable HSTS.
FIX 02
Set Content-Security-Policy
Time: 30 minutes (testing) | Impact: very high
CSP (Content-Security-Policy) tells the browser which sources of scripts, styles, and images are trusted. With CSP, even if an attacker injects malicious JavaScript onto your page, the browser refuses to execute it because it is from an unapproved source. This blocks 80% of XSS attacks.
Start with: Content-Security-Policy: default-src 'self'; script-src 'self' https://www.googletagmanager.com; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com

Adjust: add the specific third-party scripts you actually use (analytics, payment SDKs, embedded widgets). Test in Content-Security-Policy-Report-Only mode first to find what breaks.
FIX 03
Audit your subdomains
Time: 30 minutes | Impact: very high
Your main domain might be hardened. Your forgotten staging-test-12.yourdomain.com from 2 years ago might still be running an old default install of WordPress. Attackers find these via DNS enumeration in seconds. You need to know what is out there.
Run: subfinder -d yourdomain.com (or use crt.sh in browser: paste your domain). Review every subdomain. For anything you do not recognize, log into your DNS panel and delete it. For anything you DO recognize but is no longer needed, take it offline.
FIX 04
Add a cookie consent banner
Time: 20 minutes | Impact: high (NDPA compliance)
The Nigeria Data Protection Act (NDPA) 2023 Section 26 requires user consent before processing personal data. Cookies that track users (analytics, marketing, session management) qualify. A cookie consent banner is the standard mechanism. NDPC has issued ₦5.2 billion in fines this year alone, partly for this exact gap.
Drop in: CookieYes (free up to 25,000 monthly views) or Osano free tier. Both deploy via single script tag. Configure: categories for "Strictly Necessary", "Analytics", "Marketing". Block Google Analytics + Pixel until user accepts.
FIX 05
Search GitHub for your committed credentials
Time: 5 minutes | Impact: very high
Every Nigerian fintech we have disclosed to in the last 30 days had this gap: a developer committed an .env file with live production credentials to a public GitHub repo. Paystack secrets. Stripe keys. Database passwords. Search GitHub for your domain right now and scan the results.
Search: "yourdomain.com" filename:.env on github.com → search → code. Also check "FLWSECK", "sk_live_", "GOCSPX-" if your stack uses Flutterwave / Stripe / Google OAuth. If found: rotate the credentials FIRST (panic mode), then `git filter-repo` to scrub history, then add `.env*` to .gitignore.
FIX 06
Set X-Content-Type-Options + X-Frame-Options + Referrer-Policy
Time: 5 minutes | Impact: medium-high
Three small headers that block three small but real attacks. X-Content-Type-Options: nosniff stops MIME sniffing attacks. X-Frame-Options: DENY stops clickjacking. Referrer-Policy: strict-origin-when-cross-origin stops your URLs leaking sensitive query strings to third-party sites.
What to add:
X-Content-Type-Options: nosniff
X-Frame-Options: DENY (or SAMEORIGIN if you embed your own pages)
Referrer-Policy: strict-origin-when-cross-origin

Where: same place as HSTS in fix 01.
FIX 07
Patch your CMS / framework
Time: 30-90 minutes (test environment first) | Impact: very high if behind
If your site runs WordPress, Drupal, Joomla, Laravel, Django, or any other framework, check the version. Compare against the latest. If you are more than ONE major version behind, you are running known-vulnerable code. Sterling Bank's 2026 breach was an unpatched CVE that had been public for 3 months.
Check: for WordPress: view-source: on your homepage and search for generator. For others: framework documentation. Patch: always test in a staging environment first. Take a backup before patching. Document what changed.
FIX 08
Remove the Server header / framework version disclosure
Time: 5 minutes | Impact: medium
By default, your web server sends headers like Server: nginx/1.18.0 or X-Powered-By: PHP/7.4. This tells attackers exactly what software you run, which lets them look up the right CVE. Remove or generalize these.
nginx: in nginx.conf, server_tokens off;
Apache: in .htaccess, Header unset Server + Header unset X-Powered-By
Express.js: app.disable('x-powered-by')
FIX 09
Document your incident response process (1 page)
Time: 60 minutes | Impact: high (NDPA compliance + faster response)
NDPA 2023 mandates breach notification within 72 hours of awareness. Most Nigerian businesses do not have a written process. They scramble when something happens, and the 72-hour clock runs out. Write a 1-page document NOW. Five steps: (1) detect, (2) contain, (3) preserve evidence, (4) notify NDPC, (5) notify affected users. Names, phone numbers, decision tree.
Template: see Securva's NDPA compliance guide at securva.net/blog/what-is-ndpa.html. Adapt the response template. Print it. Pin it to the wall above your CTO's desk. The 72-hour clock starts BEFORE you remember where the document is.
FIX 10
Set up a 30-day re-scan reminder
Time: 2 minutes | Impact: medium-high (compounds)
Security is not a one-time fix. Code changes. New developers join. Configurations drift. The single biggest reason Nigerian websites slowly degrade is that nobody re-checks. Set a calendar reminder NOW for 30 days from today: re-run the Securva scan, compare against today's baseline, fix anything that regressed.
Calendar reminder: "Re-run security scan on yourdomain.com" → repeat every 30 days. Bookmark: https://securva.net → run scan → check headers tab. Compare to today's results.

How long the whole list takes

If you sit down with your DevOps person and a fresh terminal, you can complete fixes 1, 2, 5, 6, 8, 10 in about 90 minutes. Fixes 3 (subdomain audit), 4 (cookie consent), 7 (patching), and 9 (incident response doc) need 30-90 minutes each but spread across a week.

Total realistic timeline for all 10: about a week of part-time work. Not a 6-month project. Not a ₦5 million consulting engagement. A normal developer can do it in spare hours.

What we did NOT include

Common items you might expect on a "10 fixes" list that we deliberately left off:

  • Web Application Firewall (WAF): useful but expensive and adds latency. Wait until you have done 1-10 first.
  • Intrusion Detection System (IDS): same as WAF, advanced posture not foundational.
  • Two-factor authentication for admins: critically important but lives at the application layer, not the website-config layer. Worth its own article.
  • Database encryption at rest: foundational for compliance but outside the scope of website hardening.
  • Pen-test: useful AFTER the basics are in place. A pen-test before you have done the 10 above is just expensive validation that you forgot the basics.

The pattern in 1,180 Nigerian sites

Most Nigerian websites we scanned in 2026 were missing 6-8 of these 10 fixes. The HSTS gap alone affects 64% of the country's commercial web. The pattern is not malice. It is just nobody owning the security checklist.

If you finish fixes 1-10 above, you will be in the top 5% of Nigerian sites by basic security posture. That is a very low bar. Clearing it makes you measurably safer than your peers, satisfies NDPA Section 26 baseline compliance, and removes the most common attacker entry points.

The fix is not better tools. The fix is having a list. Now you have one.
